# Module hierarchy

> Generated by `Verilog/tests/gen_hierarchy.py` from a real elaboration by yosys 0.66+183 (`hierarchy -top`).
> Do not edit by hand - run `python3 tests/gen_module_docs.py` from `Verilog/` (in WSL) to regenerate the module docs, MODULES.md and this page.

What sits inside what, for every build top. Each top was elaborated with the file list, defines and include folders its own build uses, so `ifdef`s, generate blocks and parameters are already applied. Every module links to its page; the full list is in [MODULES.md](MODULES.md).

How to read the trees:

- `name` after a module is the instance name in its parent.
- Modules with nothing inside them that are used several times by one parent go on one line: `x4` and the instance names.
- A sub-tree is drawn in full the first time it appears on this page. Later copies that are exactly the same (same modules, same instance names, all the way down) say "same as above" and link to it, also across boards.
- "vendor" marks a part that is not ours and is not followed: FPGA primitives, PLLs, vendor IP, and the MiSTer and MEGA65 frameworks. For MiSTer and MEGA65 the tree starts at our top below the framework.
- ROM/RAM init files do not change which instances exist, so yosys was given empty stand-ins for them.
